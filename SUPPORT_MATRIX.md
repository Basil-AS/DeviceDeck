# Device support matrix

Status meanings: **Not started** = no DeviceDeck implementation; **Researching** = source/app evidence being examined; **Protocol only** = reusable frame codec exists but there is no platform discovery/UI integration; **Transport only** = platform BLE/GATT discovery and link exist, but no model protocol session or user controls; **Implemented** = app code exists but hardware validation is incomplete; **Verified** = tested on the named OS, device revision, and firmware. “Cataloged” alone never means verified.

## Evidence required to mark a feature verified

- Exact marketed model, hardware revision, regional variant, and firmware.
- OS version, Bluetooth adapter/phone, and app build.
- Read trace before and after a change; command/response decoded with confidence noted.
- Reconnect and persistence behavior.
- Whether the official app/system service must release an exclusive control connection.

For inherited realme profiles, listed controls describe mappings in the existing Android/Windows code, not verified results from a DeviceDeck build. Other feature names are investigation targets, not claims that every model supports every item.

## Current static evidence

Baseus Intelligent 2.18.0 includes model-specific UI and command paths. EP10 Pro and Bowie MF1 use RFCOMM/SPP in the observed app flow; Bowie 30 and Blade 2 use BLE, with Blade 2 in a power-device flow. A regional BLE dictionary provides UUID profiles for 149 models. DeviceDeck's unified Android/macOS/Windows/Linux applications now have EP10 Pro battery/noise controls on every platform, MF1 battery reading on every platform, Bowie 30 controls on every platform, and Blade 2 telemetry/display/timer controls on every platform; Blade 2-140 cell metrics are available on Android. These paths still need physical-device validation. [`research/baseus-reference`](research/baseus-reference) is protocol/source material, not another DeviceDeck application. The Blade 2 APK command groups are now mapped to C1/C2 in the protocol notes; port writes and reset remain withheld pending physical semantics/readback validation. Additional device profiles and physical validation remain open. See [`research/baseus-intelligent-findings.md`](research/baseus-intelligent-findings.md), [`research/baseus-ble-config-catalog.csv`](research/baseus-ble-config-catalog.csv) and [`research/baseus-reference/docs/protocol/blade-2-mobile-power.md`](research/baseus-reference/docs/protocol/blade-2-mobile-power.md). The realme Link reverse engineering remains in progress; Air 7/Air 7 Pro now also have a DeviceDeck catalog overlay on macOS, with physical-device verification still outstanding.
